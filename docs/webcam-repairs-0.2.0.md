# 無価値価値 Webカメラ版0.2.0

利用者からの4件の指摘を受けた修正。旧0.1.2のZIPを保持し、0.2.0は別名のZIP・フォルダ・HTMLにした。

## 修正
- 瞬き：元の眼球全体を4段階で縦に縮める処理を廃止。元の虹彩・白目の画素を拡縮せず、まぶたの開口で隠す40段階へ。提供閉じ目の睫毛を局所的に合わせ、開閉に18/30msの時刻基準フィルターを適用。眉と髪は動かさない。まぶた下の肌は目の領域だけ局所補完。
- 口：肌も含む差分パッチ全体をリマップする処理を廃止。差分から唇・口内を取り出し、その部分だけ32段階で開閉。閉じ口線の領域だけ肌を局所補完し、他の肌・輪郭を保持。全開度で口の外の画素が元絵と同じことを検査。
- かしげ：入力とリグの上限を左右とも±5度から±12度へ。変換行列がない場合の0.18倍の減衰を廃止し、較正済みの眼線傾きから算出。「かしげの感度」を追加。広げた角度で首メッシュが折り返さないよう、頭→胴の重みの遷移を広げた。
- アクセサリー：左右の耳飾りと衣装の房7つを元絵から分割。固定された取付部から、最大4度の減衰ばね揺れを追加。「アクセサリーの揺れ」ON/OFFと揺れ量スライダーを追加。下に隠れていた髪・衣装は選択した領域だけ局所補完した。髪や熊耳は独立物理で揺らさない。
- 選択されていない目・口の候補メッシュの変形計算を省き、40段階化による計算量増加を抑えた。

## 検査
修正用検査109項目：全口形・全開度で輪郭不変、隣接瞬き画像の連続性、元絵との静止一致、±12度＋最大体移動の見切れなし、三角形メッシュ反転なし、9アクセサリーのばね反応、物理OFF、制御された入力行列で±11度に到達、ブラウザJSエラーなし。
静止白合成の平均RGB誤差は0.117未満（0〜255尺度）。7枚の素材原本SHAは不変。
配布検査7項目：iPhoneコードなし、ZIP内HTML一致、モデル表示、ネイティブ疑似カメラの開始/停止、拒否時の案内、ブラウザエラーなし。
比較画像はdocs/verification/repair/expressions_fixed.jpg、tilt_-12.png、tilt_12.png。Mac実カメラ・OBSは未確認。顔検出器を模擬したカメラ試験を実MediaPipe試験として扱わない。

## さらに品質を上げる素材
1. 目の開き75%・50%・25%、通常の力を抜いた閉じ目。同じキャンバス・顔の位置・姿勢・眉・髪で、目の領域だけ変えた透過PNG。現在の中間は元絵からの近似なので、これがあると瞼・睫毛の形を絵柄に合わせられる。左右別レイヤーが望ましい。
2. 耳飾り・房・チェーン・宝石の部位別透過PNGと、それらを取り除いた背面の髪/衣装。現在は耳飾り2つと房7つの揺れまで。衣装の全チェーンや全宝石を個別に揺らすリグにはしていない。背面素材があると動いたときに見える模様を局所補完ではなく本来の絵で出せる。

## 再生成
Python仮想環境にrequirements-validated.txtを導入。
`python tools/prepare_character.py` → `python tools/build_character.py` → `python tools/export_webcam.py`。
テストのHTTPは作業機内部のみで使用。`python -m http.server 8089 --bind 127.0.0.1 --directory dist` で起動し、`python tests/verify_repairs.py`、`python tests/verify_webcam_distribution.py`を実行する。
